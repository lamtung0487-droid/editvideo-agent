# Editing music to picture (and picture to music), plus two archive-montage forms: map-matte and dossier / evidence board

Scope note: these notes cover (a) local music-structure analysis, cue editing craft, automatic retargeting and mixing under narration, and (b) design and timing for map-matte and dossier montages. Research was done on 2026-10-27. Several craft sources are tutorials or vendor blogs rather than primary professional texts. Each finding says which kind of source it comes from. I also checked the EditVideo repo: no `*.py` file currently imports allin1, madmom, beat_this, BeatNet, demucs or librosa, so the analysis layer would be new code.

## Q1. Local music structure analysis (beats, downbeats, bars, sections) and stem separation: accuracy, speed on an RTX 3060, licences

### Takeaway
The cleanest open stack for a local pipeline has three parts. **Beat This!** (MIT, ISMIR 2024) handles beats and downbeats. **allin1** (MIT, WASPAA 2023) handles beats, downbeats and labelled sections (intro/verse/chorus/bridge/outro...). **Demucs HTDemucs** (MIT, now archived) handles stems. madmom's *model files* are non-commercial (CC BY-NC-SA) and Essentia is AGPLv3, which are licence traps for a product. allin1 needs NATTEN, which has to be built from source on Windows, so that is the main install risk.

### Cited Findings
**allin1 (All-In-One Music Structure Analyzer)**
- Outputs tempo (BPM), beat times, downbeat times, beat positions within the bar, and functional segments. Each segment has a start, an end and one of ten labels: start, end, intro, outro, break, bridge, inst, solo, verse, chorus. Frame-level activations and embeddings at 100 FPS are optional — [GitHub mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one)
- Licence: the repo is MIT. The page gives no separate licence for the weights — [GitHub mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one)
- Dependencies: PyTorch, NATTEN (required on Linux and Windows) and madmom installed from GitHub. Audio is demixed internally with Demucs into bass/drums/other/vocals. FFmpeg is optional, for MP3 — [GitHub mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one); [PyPI allin1](https://pypi.org/project/allin1)
- Windows: NATTEN has no prebuilt package, so it must be built from source (clone, then `make`) — [GitHub mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one)
- Speed: on an RTX 4090 with an i9-10940X, the `harmonix-all` model processed 10 songs (33 min of audio) in 73 s — [GitHub mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one)
- Trained on the Harmonix Set with 8-fold cross-validation. The README gives no F1 numbers and points to the paper: Kim & Nam, "All-In-One Metrical and Functional Structure Analysis with Neighborhood Attentions on Demixed Audio", IEEE WASPAA 2023, arXiv:2307.16425 — [GitHub mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one)
- Useful extras: `-s` writes a sonification WAV (clicks on beats/downbeats plus sounds at segment boundaries mixed into the track), which is a quick audit aid. `-v` writes a visualisation PDF. `-k/--keep-byproducts` keeps the demixed stems (`./demix`) and spectrograms (`./spec`) instead of deleting them — [GitHub mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one)
- The JSON output (one file per track in `./struct`) holds `bpm`, `beats`, `downbeats`, `beat_positions` and `segments[{start,end,label}]`. Fields differ slightly between releases — [PyPI allin1](https://pypi.org/project/allin1)

**Beat This! (CPJKU)**
- Foscarin, Schlüter & Widmer, ISMIR 2024. Beat This! beats the previous state of the art in F1 *without* DBN post-processing. It scores worse on continuity metrics and can still fail on difficult or under-represented genres. The architecture alternates convolutions with transformers and uses a loss that tolerates small shifts in annotation timing — [JKU research portal](https://research.jku.at/en/publications/beat-this-accurate-beat-tracking-without-dbn-postprocessing/); [arXiv 2407.21658](https://arxiv.org/pdf/2407.21658)
- Code and published weights are MIT. Some training audio is copyrighted or under restrictive CC licences, and users must judge whether that matters for their use — [GitHub CPJKU/beat_this](https://github.com/CPJKU/beat_this)
- Checkpoints: `final0-2` (~78 MB each, the default), `small0-2` (~8.1 MB), plus fold and ablation models. It uses the first GPU and falls back to CPU. `--float16` may speed up recent GPUs. The DBN is optional (`dbn=True` needs madmom from GitHub). It returns both beats and downbeats — [GitHub CPJKU/beat_this](https://github.com/CPJKU/beat_this)
- Install: PyTorch ≥2.0, then `pip install tqdm einops soxr rotary-embedding-torch` and `pip install beat-this`. API: `File2Beats(checkpoint_path="final0", device="cuda", dbn=False)` returns `beats, downbeats`. `save_beat_tsv` writes a TSV — [GitHub CPJKU/beat_this](https://github.com/CPJKU/beat_this)
- The README gives no comparison with madmom, BeatNet or allin1 and refers to the paper's tables instead — [GitHub CPJKU/beat_this](https://github.com/CPJKU/beat_this)

**madmom**
- "all source code files are published under the BSD license", but "all model and data files are distributed under the Creative Commons Attribution-NonCommercial-ShareAlike 4.0 license". Commercial use of the models needs contact with Gerhard Widmer — [GitHub CPJKU/madmom](https://github.com/CPJKU/madmom)

**BeatNet**
- An online (real-time capable) joint beat, downbeat and meter tracker. It uses a causal CRNN plus sequential Monte Carlo particle filtering, and an "information gate" cuts the cost of the particle filter. It follows tempo and time-signature changes. Published at ISMIR 2021 — [arXiv 2108.03576](https://arxiv.org/pdf/2108.03576); [GitHub davies-w/BeatNet (fork of mjhydri/BeatNet)](https://github.com/davies-w/BeatNet)

**Essentia**
- The Python package is AGPLv3 (PyPI metadata: AGPL-3.0-only). A proprietary licence is available on request from UPF's Music Technology Group — [SIGMM 2014 Essentia article](https://sigmm.hosting.acm.org/2014/03/20/essentia-an-open-source-library-for-audio-analysis/); [depscope PyPI metadata](https://depscope.dev/pkg/pypi/essentia)

**Demucs / HTDemucs (stem separation)**
- MIT licence. The repo was archived on 1 Jan 2025 and is read-only, because the author left Meta. A fork at github.com/adefossez/demucs receives important bug fixes only — [GitHub facebookresearch/demucs](https://github.com/facebookresearch/demucs)
- Models: `htdemucs` (the default; trained on MUSDB plus 800 extra songs), `htdemucs_ft` (fine-tuned, ~4x slower, "may perform slightly better"), `htdemucs_6s` (adds guitar and piano; the piano output is poor) and `mdx_extra`. HT Demucs scores 9.0 dB SDR on MUSDB HQ, against 7.7 dB for Hybrid Demucs v3 — [GitHub facebookresearch/demucs](https://github.com/facebookresearch/demucs)
- GPU memory: at least 3 GB, about 7 GB with default arguments. `--segment` lowers memory, with a maximum of 7.8 s for HT models. The README gives roughly 1.5x track duration as a processing-time estimate; the summary I read did not say which device that applies to. `--two-stems=vocals` does a full separation and then sums the other stems, so it is no faster — [GitHub facebookresearch/demucs](https://github.com/facebookresearch/demucs)

### Inferences
- **Recommended stack:** use Beat This! (`final0`, no DBN) as the beat/downbeat source of truth (MIT, pip-installable, no NATTEN). Run allin1 for section labels where NATTEN builds; if the Windows build fails, run it under Linux/WSL. Use Demucs `htdemucs` for stems (drums for transient-safe cut points, vocals to avoid cutting through a sung word). allin1 already runs Demucs internally, so `--keep-byproducts` gives the stems for free and avoids demixing twice.
- **RTX 3060 12 GB:** no published 3060 numbers were found. The 4090 figure (33 min of audio in 73 s ≈ 0.04x real time) suggests a 3060 at a few times slower would still analyse a 3-minute cue in well under a minute. Demucs's ~7 GB default footprint fits in 12 GB. All of this is unverified and should be benchmarked once.
- **Licence hygiene:** for anything distributed or commercial, avoid madmom's bundled models (NC). The madmom DBN *code* (BSD) used as post-processing is fine. Do not ship Essentia inside closed code (AGPL). MIT-only path: Beat This! + allin1 code + Demucs.
- **Cross-check rule for automation:** downbeats from Beat This! and allin1 should agree within about one frame. Where they disagree, or where Beat This! is known to be weak (rubato, ambient, orchestral documentary cues), the pipeline should fall back to phrase-level or onset-level editing and not trust a beat grid.

### Gaps
- No published accuracy table (beat F1, downbeat F1, segment HR/PWF) was retrieved for allin1 versus Beat This! versus BeatNet on the same data. The papers (arXiv 2307.16425, 2407.21658) have them, but I did not extract numbers.
- The BeatNet licence could not be confirmed from the search snippets; check the LICENSE file in mjhydri/BeatNet.
- The librosa licence was not verified this session; it is widely reported as ISC.
- No RTX 3060 benchmarks were found for any of these tools.
- I found nothing on how these trackers handle the drumless orchestral and ambient scores typical of documentary libraries.

## Q2. How music editors cut cues to length invisibly, place buttons, stingers and hits, and when picture cuts land on beats, half-beats, phrases or off-beat (genre differences)

### Takeaway
Practitioner sources agree on cutting on a strong, repeating rhythmic event: a downbeat, a phrase boundary or the snare backbeat. Slip the edit point (mid-bar to mid-bar works) rather than cutting at bar ends, and use short crossfades (≈15 frames / 0.5 s is a starting point for atmospheric material). Trailers use a three-act shape plus a cold open and a "button" after the title. Measured music-video data shows typical shot length locks to the beat in about two thirds of clips and to the bar in some genres. Perceptual sync research suggests a picture event may sit slightly *before* its sound but must not land late.

### Cited Findings
**Cue-editing craft**
- "The snare back beat is your secret weapon": in structured tracks with drums, cut on the snare hit, which falls in the same place in every bar. Don't cut from the end of one bar to the start of the next, because that can interrupt a drum fill or cut off reverb; cut from the middle of one measure to the middle of the next and slip the edit point until it sounds right. Use the waveform: a snare shows as a tall, short-attack peak — [Film Editing Pro, "Quick Tips for Cutting Music", 24 Jan 2020](https://www.filmeditingpro.com/quick-tips-for-cutting-music-cues/)
- For tracks without strong beats, cut A→B to the required length, then try a short crossfade with "15 frames (a half-second)" as the starting point. Adjust the crossfade length and slip the edit point; slipping changes the sound without changing total length. Check the alternate versions of a stock track, since one may already fit — [Film Editing Pro](https://www.filmeditingpro.com/quick-tips-for-cutting-music-cues/)
- Cut on downbeats or phrase boundaries, hide edits with crossfades, loop sections when the picture outruns the track, and don't cut on every beat. Where the overlap falls (across a downbeat, across silence, or across dense music) changes how it sounds. If an edit feels "muddy, slow, or indecisive", shorten the overlap; if the handoff is abrupt, lengthen it — [Foxi Music blog, "How to Edit Music for Video in 2026"](https://www.foximusic.com/blog/?p=597) (stock-music vendor blog)
- A forum post quoting a songwriting book says a 30-second commercial cue must *end* at 29.5 s, with only silence and reverb tail after that. This is second-hand and unverified — [TAXI forum](https://forums.taxi.com/post531070.html)

**Trailers: structure, buttons, hits**
- Trailer editor Derek Lieu's breakdown: three acts (Introduction, Escalation, Climax) plus a cold open that hooks the audience immediately and a **button**, a short beat after the title card that leaves "a final taste" of humour, action or intrigue — [Jonny Elwyn, "How to Edit a Movie Trailer"](https://jonnyelwyn.co.uk/film-and-video-editing/how-to-edit-a-movie-trailer/) (roundup, read at excerpt level)
- Jérémy Pitard, winner of the 2019 trailer-editing contest, tightened his button with a sound effect and a TV push-in, adding a creature sound before the "coming soon" card — [Film Editing Pro, 2019 trailer contest winner](https://www.filmeditingpro.com/meet-the-winner-of-the-2019-trailer-editing-contest-jeremy-pitard/)
- Trailer editors call music the most important short-form tool, because it sets tone and rhythm fast. Learning to place "music stops, hits, and whooshes" is described as a turning point. A Making The Cut conversation covers "music math" and structure — [Jonny Elwyn trailer-editing roundups](https://jonnyelwyn.co.uk/film-and-video-editing/inside-professional-trailer-editing/) (search excerpt; individual quotes not checked on the page)

**Measured cut-to-music relationships**
- A study of music videos with Harmonix beat annotations compared each clip's most common shot duration with the beat and bar durations. About two thirds of the clips are synchronised at beat level. Four-bar pattern-level sync almost never occurs (2 videos). Alternative and Reggaeton show a strong shot/beat match (about three quarters of tracks); Country, Dance/Electro and Rock more often match the *bar* duration (about a quarter of tracks). The metric is modal shot length, not the share of individual cuts that land on beats — [arXiv 2108.00970, "Is there a 'language of music-video clips'?"](https://arxiv.org/pdf/2108.00970)
- BEAT (2026) generates trailers by choosing shots from a feature film and aligning them to music. Its core claim is that editing rhythm is elastic: "rapid cuts accompany high-energy passages while sustained shots span quieter bars". It implements this with **Bar-DP**, an energy-adaptive dynamic program that makes many-to-one bar/shot alignments, and a learned music-visual encoder (MuVA). It introduces a TrailerArena benchmark with 20+ metrics. Code release is unconfirmed — [arXiv 2605.27067](https://arxiv.org/abs/2605.27067)
- "Visual Rhythm and Beat" (Davis & Agrawala, SIGGRAPH 2018) extracts *visual beats* (motion patterns) and time-shifts them to align with musical beats, so ordinary motion looks like dancing. Code is on PyPI as `visbeat` (Python 3 port: `visbeat3`). Stanford reported in 2018 that a patent had been sought — [CVPR-W 2018 paper](https://openaccess.thecvf.com/content_cvpr_2018_workshops/papers/w49/Davis_Visual_Rhythm_and_CVPR_2018_paper.pdf); [Stanford Engineering](https://engineering.stanford.edu/magazine/article/video-editing-algorithm-gives-ordinary-motion-dance-rhythm); [PyPI visbeat](https://pypi.org/project/visbeat)

**Perceptual tolerance for picture/sound coincidence**
- ITU-R BT.1359: the detectability window is +45 ms to −125 ms and acceptability is +90 ms to −185/−190 ms, where positive means audio *leads* video. Viewers notice audio arriving early much sooner than audio arriving late. Sign conventions differ between sources. The thresholds were derived from newsreader (speech) clips — [arXiv 2212.01686](https://arxiv.org/pdf/2212.01686); [NTIA report 11-474](https://its.ntia.gov/publications/download/11-474.pdf)
- The ATSC recommendation is stricter: sound should never lead picture by more than 15 ms or lag by more than 45 ms — [TV Technology, "Keeping it all in sync"](https://www.tvtechnology.com/miscellaneous/keeping-it-all-in-sync)

### Inferences
- **Measurable cut-point rules for the pipeline:**
  1. *Music edit points* (shortening or extending the cue): only between two positions with the same bar position (downbeat→downbeat, or snare→snare in the same beat slot). Both sides should be in the same section type or energy band and in the same key/chroma neighbourhood. Prefer a transient on the incoming side to mask the join. With drums, butt-cut at the transient with a very short fade. Without drums, use an equal-power crossfade, starting around 0.5 s and searching shorter/longer. The 15-frame figure is sourced; the transient-cut fade length is my default and needs listening tests.
  2. *Picture cuts on music:* snap to the beat grid within ±1 frame, biased *early*. Per BT.1359, a visual event up to ~100 ms before its sound is tolerated, but sound leading picture by more than ~45 ms is detectable, so a cut should never land late. At 30 fps, one frame is 33 ms. Applying lip-sync thresholds to cuts is an extrapolation.
  3. *Density follows energy:* map section energy (RMS on the drum stem, or the allin1 label) to target shot length. High energy means cuts every 1–2 beats; low energy means shots spanning 1–2 bars or more. This matches BEAT's "rhythm-elastic" claim and the music-video finding that bar-level lock is common in rock and dance.
  4. *Don't cut on every beat* except in music-video or trailer climaxes. Documentary work should cut mainly on phrase and section boundaries, with narration as the master clock and music underneath. Ads and social sit in between (cut on downbeats, accent hits with a picture event).
- **Button / ending:** detect the cue's real ending (allin1 `outro`/`end` label, or the last downbeat before the decay) and *back-time* it so the final hit lands on the last picture event or end card. The cut is made earlier in the cue, at a matching-bar join. The trailer-style button is a short post-title beat with a sound hit. Back-timing is standard craft practice but was not documented in the sources above.
- **Stingers and hits:** place on picture events (title reveal, map pin, document stamp) aligned to the frame of the visual impact, with any whoosh pre-roll ending exactly there.

### Gaps
- No primary professional source (Motion Picture Sound Editors, interviews with film music editors, *The Reel World*) was reached. The cue-editing rules come from tutorials and a vendor blog.
- No quantitative study was found on documentary-specific cut/beat alignment, or on "half-beat" and off-beat cutting as a deliberate device.
- The full BEAT paper (Bar-DP rules, tolerances) was not read past the abstract.
- The "29.5 s" commercial-ending rule is unverified.

## Q3. Automatic music retargeting and remixing: research, commercial features, and what open tools can reproduce

### Takeaway
All the commercial "remix to length" features use the same recipe as the 2013 Disney/ETH *Scalable Music* paper. They segment the track, find inaudible jump points between similar segments, solve a length-constrained shortest path with dynamic programming, and finish with a small time-stretch. This can be reproduced entirely with open tools (beat tracker + chroma/timbre features + DP + crossfades), optionally stem-aware via Demucs. Generative extension (ACE-Step repaint/continuation) is a newer option, but its licences and quality need checking.

### Cited Findings
- **Scalable Music: Automatic Music Retargeting and Synthesis** (Wenner, Bazin, Sorkine-Hornung, Kim, Gross; Computer Graphics Forum / Eurographics 2013, DOI 10.1111/cgf.12054). It segments audio with automatic feature extraction and spectral clustering, then runs a length-constrained least-cost path search with dynamic programming to assemble a new piece from "inaudible, structure preserving jumps". Users can constrain where parts land, and it supports joint audio-video editing (re-fitting the soundtrack when an editor cuts scenes) — [Eurographics Digital Library](https://diglib.eg.org/items/49780664-164b-49af-ba3d-c653d83eda46); [Disney Research PDF](https://la.disneyresearch.com/wp-content/uploads/Scalable-Music-Automatic-Music-Retargeting-and-Synthesis-Paper.pdf)
- **Adobe Remix (Premiere Elements help):** stage 1 scans the clip once per session for segments that can be stitched. Stage 2 picks segments to approach the target duration "while still sounding natural", removing or looping parts. A final time-stretch makes the duration exact. Instrumental tracks work better — [Adobe Help, Music Remix](https://helpx.adobe.com/uk/premiere-elements/desktop/special-audio-effects/music-remix.html)
- **Adobe Remix (Premiere Pro beta), as tested by Larry Jordan:** results only land within ±5 s of the requested duration (a 2:56 track asked for at 30 s came out at ~34 s). Edit points are shown but not adjustable. There are two sliders: *Edit Length* (how far apart the edits are) and *Features* (weighting of timbral versus harmonic cues). He advises against using it on music with lyrics — [Larry Jordan](https://larryjordan.com/?p=147847)
- **Epidemic Sound Adapt:** 15/30/60-second presets or any duration up to 5 min. The developer API has an "adapt length" endpoint (1 s to 5 min, beta). Stems (melody, instruments, bass, drums) launched in Adapt on 4 Nov 2025 and can be muted, rebalanced or filled in if missing. Adapted tracks carry the same licence — [Epidemic Sound Adapt](https://www.epidemicsound.com/tools/adapt/); [Epidemic Sound press release 2025](https://corporate.epidemicsound.com/press-and-media/press-releases/2025/epidemic-sound-expands-adapt-functionality-to-give-creators-and-brands-more-creative-control/); [Epidemic product release updates](https://www.epidemicsound.com/blog/product-release-updates/). A Portuguese tutorial says the melody stem cannot be adapted when the track has vocals — [Epidemic PT tutorial](https://www.epidemicsound.com/pt/tools/adapt/tutorial/)
- **Infinite / Eternal Jukebox lineage:** beats are compared on pitch, timbre, loudness, duration and *position within the bar* to find jump candidates. The original used Spotify's (Echo Nest) analysis API — [Music Machinery, "Infinite Jukebox improved"](https://musicmachinery.com/2014/11/28/infinite-jukebox-improved/). Remixatron (Dave Rensin) is a command-line Python re-creation, listed as Apache-2.0 on a third-party directory — [AlternativeTo](https://alternativeto.net/software/remixatron/about/)
- **ACE-Step (generative):** v1 (3.5B, May 2025, StepFun and ACE Studio) is listed as Apache-2.0 — [HyperAI](https://hyper.ai/en/notebooks/39328). ACE-Step 1.5 supports *repainting* (regenerating a chosen section of existing audio) and *continuation* (extending a clip). VRAM claims conflict: "<4 GB" in the 1.5 README versus ≥6 GB or 20 GB+ for XL variants elsewhere — [ACE-Step 1.5 README mirror](https://huggingface.co/TTS-AGI/ACE-Step-1.5-Backup/blob/main/code/README.md); [Zeabur template](https://zeabur.com/templates/B0J8WX)

### Inferences
- **Reproducible open "remix to length" (proposed design):**
  1. Get the beat/downbeat grid from Beat This! and sections from allin1. Optionally take stems from Demucs.
  2. Compute beat-synchronous features per beat: chroma (harmony), MFCC (timbre), RMS (energy), bar position and section label.
  3. Build jump candidates *i→j* where the bar position matches (downbeat→downbeat preferred), cosine distance of chroma and timbre over a 1-bar context is below a threshold, energy difference is small, and no vocal is active across the join (vocal-stem RMS below a gate). This follows Adobe's harmonic/timbral weighting and Jordan's lyrics warning.
  4. Solve length-constrained DP (Scalable Music) for a path whose duration is within ±1 beat of the target. It must start at the intro if one is needed and end on the cue's real ending (back-timed). Penalise each jump, and penalise jumps that shorten a section below one phrase (4 or 8 bars).
  5. Apply crossfades at the joins (Q2 rules), then a final time-stretch of ≤2–3 % with a high-quality stretcher to hit the frame-exact length, as Adobe does.
  6. Stem-aware option: jump drums and bass on the grid while the "other" stem crossfades longer. This is roughly what Epidemic's stem-level Adapt exposes.
- Generative extension (ACE-Step repaint/continuation) suits stretching an ambient bed that has no repeatable structure. It risks timbre drift and licence ambiguity for 1.5, so it should be gated behind a quality check.

### Gaps
- No 2020–2026 academic paper on music retargeting/resizing beyond Scalable Music (2013) was found. Newer work, if it exists, was not reached.
- Epidemic's algorithm is undisclosed.
- Remixatron's README and licence were not verified first-hand, and its use of librosa was not confirmed.
- I found no objective metric for "invisible edit" quality; Scalable Music's perceptual evaluation was not read.

## Q4. Mixing music under narration: ducking depth, sidechain timing, frequency carving, loudness targets, intelligibility metrics

### Takeaway
The best evidence-based ducking rule is Torcoli et al. (AES/JAES 2019): keep commentary **at least 10 LU louder than music** and **at least 15 LU louder than ambience**. Non-experts prefer about 4 LU *more* separation than mixing engineers. Delivery targets: EBU R128 −23 LUFS / −1 dBTP for broadcast; Netflix −27 LKFS ±2 LU *dialogue-gated* with −2 dBTP; YouTube and Vimeo about −14 LUFS / −1 dBTP (secondary sources only).

### Cited Findings
- Torcoli, Freke-Morin, Paulus, Simon & Shirley, "Background ducking to produce esthetically pleasing audio for TV with clear speech" (AES Convention 146, 2019, best peer-reviewed paper), and "Preferred levels for background ducking..." (JAES 2019, doi 10.17743/jaes.2019.0052). They first surveyed ducking in TV documentaries, then ran a listening test with 22 normal-hearing participants on the Loudness Difference (LD) between commentary and background. Preferences varied widely. Non-experts preferred LDs ≈4 LU higher than experts, and commentary-over-music differed significantly from commentary-over-ambience. Recommendation: **LD ≥ 10 LU over music, ≥ 15 LU over ambience**. A binaural-glimpse-proportion model predicted each item's median preferred LD with a mean absolute error of 1.97 LU. The authors also note that well-tuned ducking practice is not documented in handbooks or broadcaster recommendations — [FAU CRIS record](https://cris.fau.de/publications/221136558); [FAU CRIS JAES record](https://cris.fau.de/publications/234640600); [Salford repository](https://salford-repository.worktribe.com/output/1371938/background-ducking-to-produce-esthetically-pleasing-audio-for-tv-with-clear-speech)
- Netflix: −27 LKFS average, ±2 LU, measured *dialogue-gated* (ITU BS.1770-1 with Dolby Dialogue Intelligence, so music and effects are excluded). True peak should not exceed −2 dBTP, with true-peak limiters on all beds and objects at −2.3 or lower. M&E stems: true peak −1 dBTP, with no loudness target. Dialogue is "the anchor element around which FX and Music are mixed" — [Netflix Sound Mix Specifications & Best Practices](https://backlothelp.netflix.com/hc/en-us/articles/360001794307-Netflix-Sound-Mix-Specifications-Best-Practices-v1-5); [Netflix: Loudness and True Peaks](https://backlothelp.netflix.com/hc/en-us/articles/360050414014-Loudness-and-True-Peaks-How-to-Measure-and-When-to-Flag); [Production Expert on Netflix spec](https://www.pro-tools-expert.com/home-page/2018/9/18/netflix-respond-to-our-article-on-their-new-loudness-delivery-specs). One Netflix QC page lists a looser ±3 LKFS tolerance — [Netflix Original Language Mix](https://backlothelp.netflix.com/hc/en-us/articles/115001539991)
- EBU R128: normalise to −23 LUFS; maximum true peak in production −1 dBTP — [Wikipedia, EBU R 128](https://en.wikipedia.org/wiki/EBU_R_128). Tolerance is ±1 LU per a vendor page — [editingtools.io](https://it.editingtools.io/loudness/)
- YouTube and Vimeo: −14 LUFS, −1 dBTP, typical LRA 6–8 LU (vendor comparison table, not YouTube documentation). Streaming platforms generally target −14 to −16 LUFS — [Soundbridge](https://www.soundbridge.io/loudness-normalization-a-mixing-and-mastering-guide); [editingtools.io](https://it.editingtools.io/loudness/). Podcasts are commonly −16 LUFS — [Mubert Cast docs](https://mubert.com/tools/cast/docs/loudness-lufs.md) (vendor)

### Inferences
- **Automatable ducking rule:** measure short-term loudness (BS.1770, 3 s) of narration and of the music bed over each narration span, then set the music gain so LD ≥ 10 LU (target 12–14 LU, since general audiences prefer about 4 LU more than experts). For ambience/SFX beds under narration, use LD ≥ 15 LU. Restore music to full level in narration gaps of about one bar or longer. Time the ramps to the music: ramp down just before the first word and back up on the next downbeat after the last word, so that the level changes themselves feel "edited to music".
- **Sidechain timing and frequency carving (unsourced defaults to validate by ear):** attack in the tens of milliseconds and release in the hundreds of milliseconds, or a pre-computed (look-ahead) gain envelope, since the pipeline knows narration timings in advance. Add a gentle presence dip (roughly 1–4 kHz) on the music stem only while speech is active. With Demucs stems, duck the "vocals" and "other" stems more than drums and bass, which keeps energy while clearing the speech band.
- **Delivery presets:** `youtube` = −14 LUFS integrated / −1 dBTP; `broadcast_ebu` = −23 LUFS / −1 dBTP; `netflix_like` = dialogue-gated −27 LKFS / −2 dBTP. Running ffmpeg `loudnorm`/`ebur128` as a QC gate is the natural implementation; I have not checked its dialogue-gating support.

### Gaps
- No authoritative source was found for sidechain attack/release values or for frequency-carving amounts. The defaults above are unsourced.
- Not researched: objective intelligibility metrics usable on a mix (STOI/ESTOI, SII, glimpse proportion implementations), or how Torcoli's glimpse model could be reproduced.
- YouTube's own documentation of its −14 LUFS normalisation was not reached. Only vendor tables were.
- Full texts of the Torcoli papers (per-content LD distributions, the documentary survey data) are paywalled and were not read.

## Q5. Map-matte montage: archival footage inside country/region shapes or along routes, map↔footage transitions, documentary precedents, legibility and timing

### Takeaway
The form goes back to Capra's *Why We Fight*, whose Disney-animated maps used a strict colour code (Axis territory in black) cut against archival footage. Modern references include Elastic's Emmy-winning *The Man in the High Castle* titles, where combat footage is projected across a North American map and through monuments, and the animated 3D maps in Burns/Novick's *The Vietnam War*. I found no published craft rules for timing or legibility. The rules below are derived from adjacent standards (subtitle reading time) and from documentary-ethics guidance on the provenance of footage.

### Cited Findings
- *Why We Fight* (Frank Capra, WWII). Walt Disney Productions made the animated maps, which showed Axis-occupied territory in black. Capra's editors re-cut Axis propaganda footage to argue against its makers ("damning the Axis Powers with their own images"), with Walter Huston's narration rebutting point by point — [Wikipedia, Why We Fight](https://en.wikipedia.org/wiki/Why_We_Fight); [National Archives "Unwritten Record" blog](https://unwritten-record.blogs.archives.gov/2020/09/01/why-we-fight-prelude-to-war-americas-crash-history-lesson/)
- *The Man in the High Castle* main title (Elastic; 2016 Emmy for Outstanding Main Title Design) opens with projector sounds and flickering celluloid-style images. It moves across a North American map while combat footage is projected onto and through monuments, in a tone of "yearning and doomed nostalgia" — [Art of the Title](https://www.artofthetitle.com/title/the-man-in-the-high-castle)
- *The Vietnam War* (Burns/Novick, PBS 2017) uses animated three-dimensional maps — [Axios](https://www.axios.com/2017/12/15/ken-burns-takes-on-the-vietnam-war-1513305269). Technicolor PostWorks restored damaged archival elements, applied "hundreds of titles and graphics" and graded black-and-white and colour media from 35 mm, 16 mm, Super 8 and early videotape — [Post Magazine](https://www.postmagazine.com/Publications/Post-Magazine/2018/January-1-2018/Documentary-I-The-Vietnam-War-I-.aspx)
- *Apocalypse: The Second World War* (Clarke & Costelle, 2009) is all-archive and fully colourised, with most Holocaust scenes kept in black and white. Sources disagree on how much footage is previously unseen: 50 % per the producers, 78 % per Den of Geek. None of the sources reached confirm its map style — [Den of Geek review](https://www.denofgeek.com/movies/apocalypse-second-world-war-blu-ray-review); [Cambridge Language Centre record](https://www.langcen.cam.ac.uk/resources/langf/data/fr_859.html)
- Practitioner pattern (freelance documentary brief): the map is the base layer; drone or archival clips "drop in as evidence beats on top of the map, 2 to 4 seconds each, then the map returns" — [Upwork documentary-style editor brief](https://www.upwork.com/freelance-jobs/apply/Video-Editor-for-Documentary-Style_~022059046944577423278/) (job listing seen as a search excerpt; low authority)
- Documentary practice guide: choose each visual for the factual question it answers. Do not use atmospheric footage as proof of a specific event unless its provenance supports the link. Log each asset's source and rights — [DocumentaryTube guide](https://www.documentarytube.com/blog/how-to-make-a-documentary-video-with-maps-archival-footage-and-motion-graphics/)
- Reading-time proxy: Netflix subtitles have a minimum of 5/6 s (20 frames at 24 fps) and a maximum of 7 s per event. Reading speed is set per language, e.g. Indonesian adult up to 17 characters/s, Korean adult up to 12 cps, Simplified Chinese adult up to 9 cps — [Netflix Timed Text Style Guide: General Requirements](https://backlothelp.netflix.com/hc/en-us/articles/215758617); [Netflix Indonesian TTSG](https://backlothelp.netflix.com/hc/en-us/articles/216009727); [Netflix Korean TTSG](https://backlothelp.netflix.com/hc/en-us/articles/216001127)

### Inferences
- **Design rules for an automated map-matte (proposed):**
  1. *Provenance:* footage matted inside a country shape asserts that it was filmed there and in that period. Only matte footage whose archive metadata (place and date) matches the shape; otherwise use a neutral frame. This follows the DocumentaryTube provenance rule and fits the repo's existing licence ledger.
  2. *Colour code before footage:* as in *Why We Fight*, establish one semantic fill colour per side or state first, and keep the footage inside the shape graded towards that hue (or desaturated with a coloured edge) so the code survives.
  3. *Sequence:* map establish with labels (hold ≥ the reading time of the labels, e.g. characters ÷ ~15 cps, minimum ~1 s) → the shape fills with footage (matte reveal on a music downbeat) → push into the footage until it fills the frame (map→footage transition) → 2–4 s evidence beat(s) → pull back out to the map so the next region can fill. The 2–4 s beat length is from the practitioner brief.
  4. *Legibility:* at most one moving element at a time (camera *or* matte reveal *or* route line). Keep the edge of the shape crisp (a 1–3 px stroke or soft inner glow) so the silhouette reads against busy footage. Footage inside small shapes needs a scale-up or crop to its subject, otherwise it reads as texture.
  5. *Routes:* footage along a route reads best as a line drawn at constant on-screen speed, with clip windows popping at waypoints on downbeats. Each waypoint label should be held for the reading time.
- *The Man in the High Castle* shows the "projection" variant: footage is projected *onto* geography or objects (light falloff, surface texture) rather than hard-masked. That looks more physical and less template-like than a flat alpha matte.

### Gaps
- I found no first-hand description of how Burns/Novick's map team, *Apocalypse*, or Netflix WWII series (e.g. *Greatest Events of WWII in Colour*) build or time map sequences. The 3D maps are confirmed only at the "exists" level.
- No published legibility or timing rules specific to map labels in documentary were found. The reading-speed figures are a subtitle proxy.
- No tutorial or paper specifically on footage-inside-country-shape mattes was found. Search results were dominated by stock and freelance listings.

## Q6. Dossier / evidence-board montage: documents, photos, stamps, red string, folders, typewriter text, redactions, camera moves, and avoiding the cheap-template look

### Takeaway
The canonical reference is Kyle Cooper's *Se7en* titles (1995). They were shot as macro tabletop photography of real, dense, handmade notebooks, with hand-scratched type and an analog optical assembly that kept physical accidents. It was imitated for about two decades, which is exactly why a generic copy now looks like a template. *Narcos* (Digital Kitchen) shows the archival version: real period photos re-scanned, missing material re-shot to match the era, and actual tape machines used for texture. The red-string board is a well-documented fiction trope that real investigators rarely use. It should signal a character's mindset or an argument about connections, not decorate.

### Cited Findings
- **Se7en (1995) titles:** designed by Kyle Cooper at R/GA LA with David Fincher, edited by Angus Wall, storyboarded by Wayne Coe, opticals by Pacific Title. The props were real notebooks by Clive Piercy and John Sabel, dense with handwriting, taped-in photos and artefacts, framed as John Doe preparing his diary. They were shot as close-up tabletop photography of books, shadows and backlit pages. Type was scratched into black scratchboard and smeared and jittered in the film transfer, mixed with Helvetica. Most of it was assembled by hand on an optical printer, and accidents (hooks and blades passing through) were kept. The edit is staccato, cut to Coil's remix of "Closer". The horror genre adopted the look as a house style and imitations ran for about two decades. IFC ranked it the #3 title sequence of all time — [Art of the Title, Se7en](https://www.artofthetitle.com/title/se7en/)
- **Narcos (2015) titles:** by Digital Kitchen LA (CD Tom O'Neill; 2016 Emmy nomination). They mix archival photos and footage, some taken by Escobar's family photographer "El Chino", with recreations of early-'80s espionage, in a clean sans-serif — [Art of the Title, Narcos](https://www.artofthetitle.com/title/narcos/). Most period overlays and photographs were very low resolution, so the team recreated much of them, re-scanned some archival shots at higher resolution and shot missing footage to match the era — [Homegrown interview with art director Harshit Desai](https://homegrown.co.in/homegrown-voices/the-indian-art-director-who-co-created-the-iconic-narcos-title-sequence). They deliberately "blur the lines between what's archival and what's not", lit and treated new footage to match, and rented reel-to-reel machines for an authentic tape look — [Filmsupply, "Narcos title sequence beat by beat"](https://wpengine.fm.co/filmsupply/the-narcos-title-sequence-beat-by-beat/)
- **Evidence board as trope:** a "staple of thriller and detective films and shows", also called a conspiracy board, crazy wall or murder map: media pinned to a board and linked, usually with red string. The law-enforcement analogue is the Anacapa chart for social-network analysis — [Wikipedia, Evidence board](https://en.wikipedia.org/wiki/Evidence_board). Illinois professor Shawn Gilmore says such boards "aren't commonly used in real investigations". Slate's *Decoder Ring* (Oct 2025) traced the trope with Gilmore, ex-CIA analyst Aki Peritz, and production designers from *It's Always Sunny in Philadelphia* and *Homeland*. Academic treatment: Anne Ganzert, *Serial Pinboarding in Contemporary Television* (2020) — [University of Illinois English](https://english.illinois.edu/spotlight/media/unraveling-mystery-behind-string-boards); [WNYC/Slate Decoder Ring](https://wnyc.org/story/decoder-ring--the-red-string-board-conspiracy/)
- **Redaction as an editorial device: *Reality* (2023, dir. Tina Satter).** Built from the FBI interrogation transcript of Reality Winner. When she speaks words that were redacted in the transcript, she is cut out of the frame or the image glitches. Critics split: "clever, but a bit too TV", likely to "date the film quickly", "gimmicks" that diminish the drama. Others credit it with visual variety and "coded meaning" — [In Review Online](https://inreviewonline.com/2023/05/29/reality/); [Filmmaker Magazine](https://filmmakermagazine.com/?p=119825); [FilmInk](https://www.filmink.com.au/?p=87713); [Little White Lies](https://lwlies.com/reviews/reality/)

### Inferences
- **What keeps it from looking like a template (derived from Se7en and Narcos):**
  1. *Real or credible artefacts specific to the story:* the actual archival documents and photos for the claim being made (with ledger provenance), not generic "TOP SECRET" props. Where originals are low-res, re-scan or rebuild them at period-accurate scale and typography, as Narcos did, but keep authentic items visually dominant.
  2. *Physical capture cues:* macro depth of field with a moving focal plane, real paper texture and curl, raking light with falloff, shadows from objects above the page, slight handheld or motion-control drift. In the repo this points to Blender (`blender-renderer`) or depth-based 2.5D rather than flat 2D layers. Flat, evenly lit, perfectly aligned layers are the template tell.
  3. *Process imperfections that come from a process:* scan noise, ink spread, uneven typewriter strike density, misregistered stamps. These should be generated per item (randomised but deterministic per seed) and not applied as one global overlay.
  4. *Motivated camera:* moves follow the reading order of the argument (name → date → stamp → photo), with a slow push or rack-focus, one subject at a time. Each hold should last at least the reading time of the text in focus (≈15 cps proxy, minimum ~0.8 s per Netflix's 5/6 s floor), and section changes should land on music downbeats.
  5. *Red string only when "connection" is the argument:* add string links one at a time as the narration states each link, and limit a board to a handful of nodes. Viewers read a crowded board as the trope (the "crazy wall"), which suits portraying an obsessive character but undermines a documentary's credibility.
  6. *Redaction with meaning:* animate a redaction bar only where the source document really is redacted (truth to source). Use it at most once or twice per film as a beat; critics saw *Reality*'s repeated device as gimmicky.
  7. *Typewriter text:* stagger characters at a speed the viewer can read along with, or slightly faster. Key-strike SFX should sync to glyph appearance under the BT.1359 tolerance (sound no more than ~45 ms early). The final line should land on a hit or downbeat. These are proposed rules, not sourced specs.
- **Sound for the form:** both reference sequences lean on a distinctive, texture-heavy score (Coil's industrial remix for Se7en; period tape textures for Narcos). A dossier montage pairs naturally with sparse percussion and Foley hits (stamps, paper, typewriter) placed as the "hits" from Q2.

### Gaps
- True-crime documentary graphics packages (e.g. *Making a Murderer*, *The Jinx*, *Wormwood*) and spy-thriller dossier sequences were not researched. No first-hand design interviews were found for them.
- No measured timing data was found for typewriter-text speed, document hold durations or camera-move speeds in professional dossier sequences.
- *All the President's Men* (1976), with its typewriter keys as impact sounds, is often cited as a precedent; it was not verified in this session.
- No Motionographer pieces were reached on either montage form.
